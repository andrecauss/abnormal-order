3.1 · Histórico de Demanda

Regra · doc §3.1

Para cada combinação Customer–PN, utiliza-se uma janela móvel dos 6 meses imediatamente anteriores à competência.

  • Todos os seis meses participam do cálculo.
  • Meses sem pedidos são considerados com quantidade zero.
  • Os zeros reduzem a média histórica da combinação.
  • A janela é recalculada a cada nova competência.
Historical Average Customer–PN = Soma das quantidades dos últimos 6 meses / 6
Em poucas palavras

Olha os últimos 6 meses.

Mês sem pedido conta zero.

Zero puxa a média para baixo.

Todo mês a janela anda.

Ilustrativo · média com zeros
Pedidos jan–jun = 12, 0, 6, 0, 0, 18
Σ = 36
36 / 6 = 6
Historical Average = 6

3.2 · Representatividade do Cliente

Regra · doc §3.2

Após calcular a média de cada Customer–PN, calcula-se a participação daquele cliente no total histórico do PN.

Customer Representativeness (%) = Historical Average Customer–PN / Sum of Historical Averages for PN

Essa participação será utilizada para distribuir o forecast mensal do PN.

Em poucas palavras

Compara cada cliente contra o total do mesmo PN.

Quem comprou mais historicamente recebe uma fatia maior.

A soma das fatias do PN vira 100%.

Ilustrativo · mesmo PN
Cliente A média = 6
Cliente B média = 18
Σ = 24
A = 25%, B = 75%

3.3 · Customer–PN sem histórico

Regra · doc §3.3

Quando uma combinação Customer–PN não possui histórico nos seis meses:

Representativeness = 0%

O tratamento posterior será feito pela regra de Minimum Quantity.

A mesma lógica é aplicada a clientes novos.

Em poucas palavras

Sem histórico, não há fatia histórica.

A representatividade começa em zero.

O mínimo do domínio 02 decide o piso depois.

Ilustrativo · cliente novo
Cliente C sem histórico
Representativeness = 0%
Segue para a regra de Minimum Quantity no domínio 02

3.4 · Override manual

Regra · doc §3.4

É permitido realizar ajuste manual da quota de um Customer–PN.

Exemplo de aplicação:

  • mudança de código de cliente;
  • necessidade de preservar uma referência histórica que não existe na nova chave;
  • situações excepcionais conhecidas pelo negócio.

O override:

  • vale somente para a competência específica;
  • não exige rebalanceamento das quotas dos demais clientes;
  • pode fazer com que a soma das quotas individuais seja diferente do forecast total do PN;
  • na competência seguinte, o cálculo volta automaticamente à metodologia padrão, salvo novo override.
Em poucas palavras

Dá para corrigir uma quota manualmente.

Vale só para aquele mês.

Não mexe nas quotas dos outros clientes.

No mês seguinte, volta ao cálculo padrão.

Ilustrativo · override
Cliente mudou de código
Quota calculada = 0
Override manual = 40 só nesta competência
Mês seguinte volta ao cálculo padrão
Demais clientes não são rebalanceados

3.5 · Forecast mensal

Regra · doc §3.5

O forecast é recebido no nível PN.

O forecast do PN é distribuído aos clientes conforme a representatividade histórica.

Forecast Customer–PN = Forecast PN × Customer Representativeness (%)
Em poucas palavras

O forecast chega por PN.

A fatia histórica separa esse total por cliente.

O resultado vira Forecast Customer–PN.

Ilustrativo · distribuição
Forecast PN = 200
A: 200 × 25% = 50
B: 200 × 75% = 150
Forecast Customer–PN: A = 50, B = 150
